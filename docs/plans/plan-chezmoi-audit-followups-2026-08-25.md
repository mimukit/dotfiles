# Plan: chezmoi audit follow-ups
Grilled: 2026-08-25

## Context

An audit of this chezmoi repo on 2026-08-25 produced 19 findings. Thirteen were fixed and committed the same day, in commits `830b63d` through `a94c524`. Five were deferred for a decision, and one more surfaced while fixing the rest. This plan covers those six.

The deferred set is not a leftovers pile. Two of them are the reason the other four keep coming back: with no CI, a broken alias sat in `.zshrc` undetected until someone read it, and with no `.chezmoi.toml.tmpl` consumer, absolute paths keep getting re-added by export scripts. Fixing the mechanical items without the check that holds them fixed just resets the clock.

Success means: `shellcheck` is clean across every tracked script, no tracked file that we own names `/Users/mukit`, `chezmoi apply` on a new Mac installs the Brewfile without a manual step, CI blocks a regression in any of those, and a clone of the repo costs about 10 MB instead of 60 MB.

## Design decisions (settled)

| Decision | Resolution |
|----------|-----------|
| Git history weight | Rewrite with `git-filter-repo`. 76.6 MB of 91.5 MB of history blobs belong to paths gone from HEAD. The repo has 0 forks and 2 stars, so a force-push breaks no one else's clone. |
| What CI runs | Three jobs: `shellcheck` over all tracked shell, `gitleaks` for credentials, and a chezmoi job that renders every template and dry-run applies against a throwaway `HOME`. Markdown and TOML syntax checks were dropped as redundant, because the `modify_` scripts already fail loudly on bad input. |
| CI triggers | `push`, `pull_request`, and a weekly `schedule`. Direct commits to `main` are the normal habit here, and `afkkit` and `prkit` both open PRs, so the trigger set has to cover both. |
| Bootstrap scope | One `run_onchange_` script keyed on the Brewfile hash, running plain `brew bundle`, and nothing else. `ya pkg install`, `mise install` and the amix vimrc clone stay manual, because each added step is another way for `chezmoi apply` to fail halfway. |
| Bootstrap failure behaviour | Guard on `command -v brew` so a machine or CI runner without Homebrew skips cleanly, then let real failures stop the apply. `\|\| true` was rejected: a bootstrap that fails silently is worse than one that stops you. |
| Dead scripts | Delete all five unprefixed scripts. `brew_permission.sh` chowns fifteen Intel-only `/usr/local` paths on an `arm64` machine; `brew.sh` hardcodes 134 packages against a 194-package Brewfile that `brew_apps_restore.sh` already installs from; `setup_server.sh`, `setup_ssh.sh` and `vim.sh` have zero references and `vim.sh` clones a vim config you replaced with LazyVim. All five stay recoverable from git history. |
| Item 15 (the `executable_` prefix) | Dissolved. Deleting those five leaves nothing in `private_dot_local/bin` without the prefix, so there is no prefix work left to do. |
| Portable Claude paths | Widen the `__HOME__` token to a substring swap in `claude_settings_export.sh` and `modify_settings.json.tmpl`. The Orca pair keeps its narrower `startswith` form, because Orca stores whole-path values while Claude embeds a path mid-string. |
| Which hardcoded paths get fixed | Only the four files we own. The nine sites in `dot_codex/private_hooks.json` are written by Orca and herdr and get left alone, on the same rule the repo already applies to vendor hook entries. The five line-1 comment headers in `dot_config/tmuxinator/*.yml` and `dot_config/topgrade.toml` are regenerated by those tools and are cosmetic. |
| `gitleaks` scope | Tree on every push, full history on the weekly schedule. After Phase 5 the history is small enough that a full scan is cheap, but the split keeps push-time feedback fast either way. |
| Plan and QA docs in the rewrite | Keep `docs/plans` and `docs/qa`. A few KB, and the only record of why these changes happened. |
| Rewrite fallback | `git bundle` the pre-rewrite history to a file outside the repo before force-pushing. Pushing the old history to a branch was rejected, because it keeps the blobs alive on the remote and defeats the rewrite. |
| Ordering | Code cleanup, then paths, then bootstrap, then CI, then the rewrite. CI lands after the code it checks is already clean, so it is green on its first run rather than red. The rewrite goes last because it is the one step that cannot be undone with `git revert`. |

## Approach

Five phases, each independently shippable. The work reuses three things already in the repo rather than inventing them: the `__HOME__` placeholder convention from the Orca exporter and its `modify_` script; the deny-list export pattern shared by the Orca, Claude and Codex exporters; and the `.keep` placeholder convention used to declare a directory that git cannot otherwise carry.

Rejected alternatives, one line each. A hand-run `bootstrap.sh` instead of `run_onchange_` was rejected because it is one more thing to remember on the machine where you have the least context. Auditing the deleted history for credentials before rewriting was offered and declined, so Phase 5 keeps a cheap version of it: run `gitleaks` against the unrewritten history once, before the rewrite destroys the evidence.

### Phase 1: delete the dead scripts and clear the shellcheck backlog (built 2026-08-25)

Deleting the five dead scripts removes 17 of the 24 shellcheck warnings and dissolves item 15 outright. Seven warnings across three files remain. Phase 4 cannot go green until this is done.

- `git rm` five scripts from `private_dot_local/bin`: `brew.sh`, `brew_permission.sh`, `setup_server.sh`, `setup_ssh.sh`, `vim.sh`. Confirm zero references first with a fixed-string grep, not a regex; an unescaped `.` in `brew.sh` produced two false-positive matches during the grill.
- Remove the corresponding files from `~/.local/bin`, which chezmoi does not delete on its own.
- Add a targeted `# shellcheck disable=SC2088` with a stated reason to the four tilde sites in `private_dot_local/bin/executable_rm-guard`. These are deliberate `case` patterns matching a literal `~`, not a failed expansion, so the disable comment is the fix rather than a change to the code.
- Remove or use the two unused colour variables in `private_dot_local/bin/executable_orca_settings_export.sh` (SC2034).
- Single-quote the trap at `private_dot_local/bin/executable_brew_apps_cleanup.sh:87` so `$TMP_DIR` expands when the trap fires rather than when it is installed (SC2064).
- Verify: `shellcheck -S warning` over every tracked script exits 0.

### Phase 2: replace the hardcoded home paths (built 2026-08-25)

Four files we own name `/Users/mukit` in eight places. `.chezmoi.toml.tmpl` already exposes `.chezmoi.homeDir` and a `home` data key for exactly this.

- `private_dot_gitconfig` becomes a template. Two sites: `gpg.ssh.allowedSignersFile` and `gpg.ssh.program`. The file already uses `~` for `signingkey` and `excludesfile`, so the inconsistency is the bug, not the absolute path.
- `dot_config/iterm2/symlink_AppSupport` becomes `symlink_AppSupport.tmpl`.
- `dot_config/mise/config.toml` becomes a template for `trusted_config_paths`.
- `.chezmoitemplates/claude-settings.json` has four permission entries naming the home directory, each with the path embedded mid-string, as in `Bash(bash /Users/mukit/.claude/statusline.sh)`. A raw `{{ }}` expression cannot live in that file, because `claude_settings_export.sh` regenerates it from the live settings on every `czs` and would overwrite it. Instead, widen the `__HOME__` convention: the exporter substitutes `$HOME` for the token anywhere in a string, and `modify_settings.json.tmpl` reverses it with a `gsub` rather than the Orca script's `startswith`.
- Document the split in both files, so a later reader does not "fix" the Orca script to match the Claude one. Orca stores whole-path values and its narrower form is correct there.
- Verify: after the change, `czs` followed by `chezmoi apply` is still a byte-for-byte no-op on `~/.claude/settings.json`. This is the round trip that would silently regress.

### Phase 3: add the Brewfile bootstrap (built 2026-08-25)

- Add `.chezmoiscripts/run_onchange_install-packages.sh.tmpl` carrying the Brewfile's hash in a comment, so it re-runs only when the Brewfile changes.
- Guard the body on `command -v brew`, which is what keeps it from firing inside the CI runner added in Phase 4.
- Run plain `brew bundle --file="$HOME/.config/brew/Brewfile"`. No `--cleanup`, which would make an apply destructive and duplicate `brew_apps_cleanup.sh`.
- Let a genuine failure exit non-zero and stop the apply.
- Update the README bootstrap section to say what is now automatic and what is still manual.
- Verify: touch the Brewfile, confirm the script fires once; apply again unchanged, confirm it does not.

### Phase 4: add CI (built 2026-08-25)

One workflow at `.github/workflows/ci.yml`, triggered on `push`, `pull_request`, and a weekly `schedule`.

- **shellcheck.** Every tracked shell script, plus the two `modify_` templates rendered through `chezmoi execute-template` first, since they are shell but not valid shell until rendered.
- **gitleaks.** Working tree on `push` and `pull_request`; full history only on the `schedule` run. The history is worth scanning here because it has carried an Obsidian vault and a Raycast settings backup on a public repo.
- **chezmoi.** Install chezmoi, run `chezmoi execute-template` over every template, then `chezmoi apply --dry-run` against a throwaway `HOME`. Confirmed viable during the grill: a dry run against a temporary destination exits 0 both with and without a rendered config, and neither the 1Password socket path nor the `gh` credential helper breaks it. Use `chezmoi verify --exclude=externals`, because a `git-repo` external makes plain `verify` exit 1 even when nothing is pending.
- Add `gitleaks` and `git-filter-repo` to `dot_config/brew/Brewfile` so local runs match CI. `shellcheck` is already there.
- Verify: the first CI run on `main` is green without any follow-up fix.

### Phase 5: rewrite the history

The destructive step, and the only one that cannot run until Phases 1 to 4 are committed and pushed. It needs a known-good remote state to compare against.

**Pre-scan result, 2026-08-25.** `gitleaks git .` scanned 1143 commits and 20.78 MB and found no leaks. Nothing in the removed Obsidian vault or Raycast backup needs rotating. That question is closed, and the rewrite can proceed on size grounds alone.

**Verified strip list.** Each prefix below was checked with `git ls-files <prefix>` and has zero live files, so stripping it cannot remove present-day content. Total 72.8 MB of 76.7 MB dead weight.

| prefix | dead weight |
|--------|------------|
| `dot_config/icons` | 33.40 MB |
| `private_documents` | 18.71 MB |
| `dot_warp` | 10.52 MB |
| `dot_config/raycast/extensions` | 7.94 MB |
| `dot_config/zellij/plugins` | 1.35 MB |
| `dot_config/yazi/flavors` | 0.79 MB |
| `dot_config/private_fish` | 0.13 MB |

**Do not strip `dot_config/raycast`, `dot_config/cursor`, `dot_config/zellij` or `dot_config/yazi` at directory level.** All four still hold live files, and a tree-level survey makes them look dead because their old revisions dominate the byte count. `dot_config/cursor/profiles` alone has 3 live files under 1.08 MB of dead revisions. Strip the exact prefixes in the table, nothing shorter.

The runbook, after Phases 1 to 4 are pushed:

```sh
cd ~/.local/share/chezmoi
git bundle create ~/Desktop/dotfiles-pre-rewrite.bundle --all   # the only way back

SCRATCH=$(mktemp -d) && git clone --no-local . "$SCRATCH/dotfiles" && cd "$SCRATCH/dotfiles"
git filter-repo --force \
  --path dot_config/icons --path private_documents --path dot_warp \
  --path dot_config/raycast/extensions --path dot_config/zellij/plugins \
  --path dot_config/yazi/flavors --path dot_config/private_fish \
  --invert-paths

# The check that proves only history was dropped, never content.
diff <(git ls-tree -r HEAD --name-only) \
     <(cd ~/.local/share/chezmoi && git ls-tree -r HEAD --name-only) && echo "trees identical"

git remote add origin git@github.com:mimukit/dotfiles.git
git push --force origin main
```

Then re-point the live source dir at the rewritten history and confirm nothing moved:

```sh
cd ~/.local/share/chezmoi && git fetch origin && git reset --hard origin/main
chezmoi status                      # expect empty
chezmoi verify --exclude=externals  # expect exit 0
du -sh .git                         # expect roughly 10 MB, down from 60 MB
```

Delete the bundle once that passes.

## Open questions

None. The frontier closed during the 2026-08-25 grill. Two items are worth watching during the build rather than deciding now:

- Phase 2 leaves the repo with two forms of the `__HOME__` convention, a `gsub` for Claude and a `startswith` for Orca. If a third app needs the treatment, that is the moment to unify them rather than adding a third variant.
- Phase 5's blob survey may turn up trees beyond the six listed. Re-run the survey against the scratch clone rather than trusting this list.

## Non-goals

- **Linux portability.** Every config here targets macOS, settled during the audit. `.chezmoiignore` stays untemplated.
- **Automated tests for the shell scripts.** `disk_cleanup.sh` has a `CACHE_CLEANUP_TEST_MODE` and nothing exercises it, but standing up a test suite is a separate piece of work.
- **Changing the Orca, Claude Code or Codex `modify_` design.** All three are verified no-ops as of 2026-08-25 and are the model this plan borrows from, not a target.
- **Unpublishing what the public repo has already served.** The Phase 5 rewrite shrinks future clones. It does not remove anything from GitHub's own object store or from any copy already taken.
- **Rewriting the nine vendor paths in `dot_codex/private_hooks.json`.** Orca and herdr write those and rewrite them on upgrade.
